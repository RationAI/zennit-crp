# CRP gallery v2 — new models (M3/M4 DINOv3) + competing-XAI comparison + OOD counts

Extension of the static CRP gallery (`webapp/crp_gallery/`, generator
`experiments/crp_gallery.py`) to the register-bearing DINOv3 models and a new
per-sample **competing-XAI comparison** row, plus a per-sample **OOD (outlier)
token count**. Builds on `dualsite_gallery.md` (the dual-site norm maps) and the
XAI-34 register study (`e2_saliency_overlap.md`, `step3_occlusion.md`,
`step4_saliency_compare.md`).

### M4 assembly

M4 has no local checkpoint: the classifier is assembled in
`crp_gallery.load_model` under `--model-source dinov3_in1k` — timm DINOv3-B/16
backbone (`num_classes=0`, `img_size=256`) + the public canvit IN1k linear head

pre-logits), wrapped as one module so `CondAttribution` sees a single classifier.

`eval_dinov3_in1k_probe.py::load_in1k_linear_head`. FunnyBirds M3 loads via the
normal `model_io.load_probe` checkpoint path (no gallery change needed).

## New feature 1 — competing-XAI saliency row

New module **`experiments/xai_methods.py`** is the single home for the non-CRP
saliency baselines, factored out of `registers_e2_overlap.py` /
`registers_saliency_compare.py` (see the "reuse" note in the cleanup log). It is
generalised over the ViT prefix-token count and patch grid, so one code path
serves the standard ViTs (1 cls prefix, 14×14) and DINOv3 (1 cls + 4 register =
5 prefix, 16×16). Methods, all returning a patch-grid map:

* `lrp_patch` — the `cp_lrp_baseline` AttnLRP relevance, |R| summed per 16×16
  patch (patch-aggregated so it sits in the same row).
* `chefer_relevance` — Chefer/Gur/Wolf CVPR'21 grad-weighted attention rollout,
  class-conditional (needs `fused_attn=False` + `attn_drop` hooks + input
  `requires_grad`).
* `attention_rollout` — Abnar & Zuidema rollout (class-agnostic; CLS→patch row).
* `occlusion_deltap` — occlusion Δp⁺: per-patch mean-colour mask, positive drop
  in the predicted-class softmax probability (grid² forwards).

In the gallery these are generated by `save_sample_xai` (model-level,
composite-independent) and stored at md level:
`figures/<md>/_sample_xai/<method>/<key>.png`. Every map is class-conditional on
the model's **own predicted class** for that image; all four are patch-aggregated
and rendered with the same percentile-clip normalization (`render_patch_map`,
inferno). The web renders a labelled row `input | LRP | Chefer | rollout |
occlusion`, each with a short provenance caption (`METHOD_CAPTIONS`, surfaced in
the manifest under `xai_captions`/`xai_order`).

## New feature 2 — OOD (outlier) token counts + DINOv3-aware dual-site maps

`save_sample_ood` (in the gallery) generalises the dual-site norm map to any
prefix count: per sample it hooks both sites (`blocks[i]` output = residual
stream; `attn.proj_drop` = attention output projection), computes per-token L2
norms for all 12 blocks, and flags patch outliers by the per-sample μ+4σ rule
over that sample's patch tokens **excluding all prefix tokens** (cls + 4
registers for DINOv3). The figure stacks the two sites (2×6 block grids,
viridis, magenta outlier boxes); for DINOv3 the **register-token norms are shown
distinctly** in a cyan-bordered magma strip below each block panel, with a
`reg×N` count of registers exceeding the same threshold.

Output: `figures/<md>/_normmaps/<key>.png` (replaces the external
`registers_actmaps_dualsite.py` webapp deploy — that script stays as the
register-study figure/npz producer). The **OOD scalar** = number of patch tokens
flagged at any block, union over both sites, written to `figures/<md>/_ood.json`
and surfaced per sample in the manifest as `ood_tokens`, shown as a pill in the
web sample panel.

## Manifest schema additions

Per sample record (`models → instances → samples → <key>`):

* `xai`: `{method: relpath}` for `lrp/chefer/rollout/occlusion` (md-level).
* `ood_tokens`: int — OOD patch-token count (union over sites), or null.
* (existing) `image`, `heat`, `normmap`, `layers`.

Top-level: `xai_order` (method order) and `xai_captions` (provenance strings,
from `xai_methods.METHOD_CAPTIONS`). New CLI: `crp_gallery sample-xai` backfills
the model-level extras (XAI row + OOD maps/counts) for existing tracked jobs,
deduped per model. Normal `compute`/`replay`/`samples` also generate them
idempotently (defensive: a failure warns but never aborts the CRP build).

## Reproduce

```
# M4 (long pole — imagenet FV over the 10k class-diverse subset, both sites):
python -m experiments.crp_gallery compute --base vit_dinov3_base --dataset imagenet \
  --config cp_lrp_baseline --site {proj_drop,residual} --blocks 0..11 --concept embed_dim \
  --n 5 --n-ref 6 --plot heat_rf --classes 0..9 --n-rank 8 --model-source dinov3_in1k
# M3:
python -m experiments.crp_gallery compute --base vit_dinov3_small --dataset funny_birds \
  --config cp_lrp_baseline --site {proj_drop,residual} --blocks 0..11 --concept embed_dim \
  --n 5 --n-ref 6 --plot heat_rf --n-rank 8
# M1 regen (invalidate the stale-weights FV cache first):
rm -rf {~/.cache/zennit-crp,data}/crp_gallery_cache/fv/vit_small_funny_birds
python -m experiments.crp_gallery compute --base vit_small --dataset funny_birds \
  --config cp_lrp_baseline --site {proj_drop,residual} --blocks 0..11 --concept embed_dim \
  --checkpoint data/runs/finetune_vit_small_funny-birds-train-clean/2026-07-26_160337/best.pt
# extras (XAI row + OOD) for all models, then verify:
python -m experiments.crp_gallery sample-xai
python -m experiments.crp_gallery manifest
```

Drivers: `scratchpad/m4_driver.sh` (log `data/logs/m4_gallery.log`),
`scratchpad/m3m1_driver.sh` (log `data/logs/m3m1_gallery.log`). GPU-lock
protocol: acquire/release per phase.

## Cleanup log (deletions + justification)

### Deletions applied
- `webapp/crp_gallery/jobs.jsonl`: removed the stale `vit_small/funny_birds/sae/1536` job line. M1's weights were retrained (2026-07-26); that SAE was trained on the OLD activations, its gallery figures were already absent from disk and the manifest, and SAE for the new models is a deferred step. A future M1 SAE instance requires retraining the SAE on the current weights first.
- `experiments/**/__pycache__`: removed (regenerable bytecode).

### Kept deliberately (NOT deleted)
- All `experiments/scripts/registers_*.py` and `residual_flow_*.py`: every one is cited by a journal entry as its reproduction script (E1/E2/E2v2/step1c/position_freq/token_flow/occlusion/severity/residual-flow/actmaps-dualsite). Deleting any would break a journal reproduction reference. Conservative keep.
- `webapp/residual_flow/` per-model pages: current (4-model residual-flow entry).
- `data/logs/*.log`, `data/results/**`, `data/runs/**`: durable evidence / reproduction inputs — untouched per instruction.

### Inconsistencies
- Instance coverage: vit_base_imagenet has {embed_dim, sae_m1536}; the other three models have {embed_dim} only (SAE deferred for the new models; M1 SAE stale-removed). This is intentional, not a gap.
- All models now carry the same sample sub-figures: input, LRP relevance heat, competing-XAI row (LRP|Chefer|rollout|occlusion), dual-site OOD norm maps + OOD count, local detector analysis.
